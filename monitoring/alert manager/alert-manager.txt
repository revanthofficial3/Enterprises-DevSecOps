ALERTMANAGER SETUP, ALERTING AND EMAIL NOTIFICATION
====================================================

Purpose
-------
Alertmanager receives alerts generated by Prometheus, groups and routes them,
and sends notifications to configured receivers.

In this project, Alertmanager is integrated with Gmail SMTP so that Kubernetes
monitoring alerts can be delivered through email.

Architecture
------------
Kubernetes / Infrastructure
          |
          v
      Prometheus
          |
          | Alert
          v
     Alertmanager
          |
          | SMTP
          v
      Gmail SMTP
          |
          v
    Email Notification


1. CHECK PREREQUISITES
----------------------

Check Kubernetes:

    kubectl get nodes

Check monitoring namespace:

    kubectl get namespace monitoring

Check Helm:

    helm version


2. INSTALL ALERTMANAGER
-----------------------

If kube-prometheus-stack is used, Alertmanager is installed as part of the
monitoring stack.

Add the repository:

    helm repo add prometheus-community https://prometheus-community.github.io/helm-charts

Update:

    helm repo update

Install the monitoring stack if it is not already installed:

    helm install monitoring prometheus-community/kube-prometheus-stack \
      --namespace monitoring \
      --create-namespace


3. CHECK ALERTMANAGER POD
-------------------------

    kubectl get pods -n monitoring | grep alertmanager

The project Alertmanager Pod should be Running and ready.


4. CHECK ALERTMANAGER SERVICE
-----------------------------

    kubectl get svc -n monitoring | grep alertmanager


5. EXPOSE ALERTMANAGER USING NODEPORT
-------------------------------------

The project exposes Alertmanager through NodePort 30093.

Change the service to NodePort:

    kubectl patch svc monitoring-kube-prometheus-alertmanager \
      -n monitoring \
      -p '{"spec":{"type":"NodePort"}}'

Set NodePort 30093:

    kubectl patch svc monitoring-kube-prometheus-alertmanager \
      -n monitoring \
      -p '{"spec":{"ports":[{"name":"http-web","port":9093,"protocol":"TCP","targetPort":9093,"nodePort":30093}]}}'

Verify:

    kubectl get svc -n monitoring


6. ACCESS ALERTMANAGER
----------------------

Open:

    http://<KUBERNETES-NODE-PUBLIC-IP>:30093

Example project URL:

    http://44.211.48.2:30093


7. CHECK ALERTMANAGER LOGS
--------------------------

    kubectl logs -n monitoring <alertmanager-pod-name>

For live logs:

    kubectl logs -f -n monitoring <alertmanager-pod-name>


8. CHECK ALERTMANAGER STATUS
----------------------------

    kubectl get pods -n monitoring | grep alertmanager

    kubectl get svc -n monitoring | grep alertmanager

    helm status monitoring -n monitoring


9. PROMETHEUS TO ALERTMANAGER FLOW
-----------------------------------

Prometheus evaluates alert rules.

When an alert becomes firing:

    Prometheus
        |
        v
    Alertmanager
        |
        +--> Group
        |
        +--> Route
        |
        +--> Receiver
        |
        v
      Email


10. GMAIL SMTP REQUIREMENTS
---------------------------

For Gmail SMTP authentication, use:

    SMTP Host:
    smtp.gmail.com

    SMTP Port:
    587

    TLS:
    enabled

Use a Gmail App Password instead of a normal Gmail account password.

DO NOT commit the App Password to GitHub.


11. ALERTMANAGER SMTP CONFIGURATION
-----------------------------------

The project uses the following configuration concept:

    global:
      smtp_smarthost: "smtp.gmail.com:587"
      smtp_from: "<YOUR_GMAIL_ADDRESS>"
      smtp_auth_username: "<YOUR_GMAIL_ADDRESS>"
      smtp_auth_password: "<GMAIL_APP_PASSWORD>"
      smtp_require_tls: true

Receiver:

    receivers:
      - name: email
        email_configs:
          - to: "<RECEIVER_EMAIL_ADDRESS>"


12. IMPORTANT SECURITY RULE
---------------------------

Never place real credentials directly in a public GitHub repository.

Do NOT commit:

    smtp_auth_password
    Gmail App Password
    AWS credentials
    Jenkins passwords
    DockerHub passwords
    Nexus passwords
    Kubernetes Secrets
    SSH private keys


13. APPLY ALERTMANAGER CONFIGURATION
------------------------------------

If using a Kubernetes Secret/configuration managed by the monitoring stack,
apply the appropriate Kubernetes configuration and restart/reconcile the
Alertmanager resource.

Check the current Alertmanager resources:

    kubectl get alertmanager -n monitoring

Check the generated Secret/configuration:

    kubectl get secrets -n monitoring | grep alertmanager


14. CHECK ALERTMANAGER CONFIGURATION
------------------------------------

Open:

    http://<KUBERNETES-NODE-PUBLIC-IP>:30093

Use:

    Status
    Settings

Verify that Alertmanager is running with the expected configuration.

    Prometheus
        |

    Alertmanager
        |
        v

23. AWS SECURITY GROUP
----------------------

If Alertmanager is exposed through NodePort 30093, allow the required TCP
port in the Kubernetes node EC2 Security Group.

Required project port:

    TCP 30093

Prefer restricting access to trusted source IPs.

----------------------

PROJECT RESULT
--------------

Alertmanager successfully receives Prometheus alerts, processes and routes
them, and sends email notifications through Gmail SMTP.

The completed project demonstrates an end-to-end monitoring and alerting flow:

    Kubernetes
        ->
    Prometheus
        ->
    Alertmanager
        ->
    Gmail SMTP
        ->
    Email Notification
