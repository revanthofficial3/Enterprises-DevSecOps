KUBERNETES WORKER NODE SETUP
============================

Purpose
-------
This document explains how to create and configure a Kubernetes worker node
on Ubuntu and join it to an existing kubeadm-based Kubernetes cluster.

The worker node is responsible for running application workloads scheduled by
the Kubernetes control plane.

Project architecture:

    k8s-master
        |
        | Kubernetes API
        v
    k8s-worker
        |
        +--> containerd
        +--> kubelet
        +--> kubeadm
        +--> Application Pods


1. SERVER REQUIREMENTS
----------------------

Recommended:

    Ubuntu 24.04 LTS
    2+ CPU
    2 GB+ RAM
    20 GB+ disk
    Stable private IP
    Network connectivity to the Kubernetes master

Check OS:

    cat /etc/os-release

Check CPU:

    nproc

Check memory:

    free -h

Check IP:

    hostname -I


2. SET HOSTNAME
---------------

Set the worker hostname:

    sudo hostnamectl set-hostname k8s-worker

Verify:

    hostname


3. UPDATE THE SYSTEM
---------------------

    sudo apt update
    sudo apt upgrade -y


4. DISABLE SWAP
---------------

Check:

    swapon --show

Disable:

    sudo swapoff -a

Disable permanently:

    sudo sed -i '/ swap / s/^/#/' /etc/fstab

Verify:

    free -h

Swap should show 0.


5. LOAD REQUIRED KERNEL MODULES
-------------------------------

    sudo tee /etc/modules-load.d/k8s.conf <<EOF
    overlay
    br_netfilter
    EOF

Load:

    sudo modprobe overlay
    sudo modprobe br_netfilter

Verify:

    lsmod | grep overlay
    lsmod | grep br_netfilter


6. CONFIGURE KERNEL NETWORK SETTINGS
-------------------------------------

    sudo tee /etc/sysctl.d/k8s.conf <<EOF
    net.bridge.bridge-nf-call-iptables = 1
    net.bridge.bridge-nf-call-ip6tables = 1
    net.ipv4.ip_forward = 1
    EOF

Apply:

    sudo sysctl --system

Verify:

    sysctl net.ipv4.ip_forward


7. INSTALL CONTAINERD
---------------------

Install:

    sudo apt update
    sudo apt install -y containerd

Create configuration directory:

    sudo mkdir -p /etc/containerd

Generate configuration:

    sudo containerd config default | sudo tee /etc/containerd/config.toml

Enable systemd cgroups:

    sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

Restart:

    sudo systemctl restart containerd

Enable at boot:

    sudo systemctl enable containerd

Check:

    sudo systemctl status containerd

Expected:

    active (running)


8. INSTALL KUBEADM AND KUBELET
------------------------------

Install prerequisites:

    sudo apt update
    sudo apt install -y apt-transport-https ca-certificates curl gpg

Create keyring directory:

    sudo mkdir -p -m 755 /etc/apt/keyrings

Download Kubernetes signing key:

    curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.34/deb/Release.key \
      | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

Add repository:

    echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.34/deb/ /' \
      | sudo tee /etc/apt/sources.list.d/kubernetes.list

Update:

    sudo apt update

Install kubeadm and kubelet:

    sudo apt install -y kubeadm kubelet kubectl

Hold versions:

    sudo apt-mark hold kubeadm kubelet kubectl

Enable kubelet:

    sudo systemctl enable kubelet


9. CHECK KUBERNETES VERSIONS
----------------------------

    kubeadm version

    kubelet --version

    kubectl version --client


10. VERIFY NETWORK CONNECTIVITY TO MASTER
-----------------------------------------

The worker must be able to reach the Kubernetes API server on TCP 6443.

Check connectivity:

    nc -vz <MASTER_PRIVATE_IP> 6443

Example:

    nc -vz 172.31.10.216 6443

If netcat is not installed:

    sudo apt install -y netcat-openbsd


11. JOIN THE WORKER TO THE CLUSTER
----------------------------------

On the Kubernetes master, generate the join command:

    kubeadm token create --print-join-command

Example format:

    sudo kubeadm join <MASTER_PRIVATE_IP>:6443 \
      --token <TOKEN> \
      --discovery-token-ca-cert-hash sha256:<HASH>

Copy the complete command.

Run that command on the worker:

    sudo kubeadm join <MASTER_PRIVATE_IP>:6443 \
      --token <TOKEN> \
      --discovery-token-ca-cert-hash sha256:<HASH>

IMPORTANT:
The token and discovery hash are generated by the master. Do not invent them.


12. VERIFY WORKER JOIN
----------------------

Go to the master node.

Run:

    kubectl get nodes

Expected:

    NAME           STATUS   ROLES
    k8s-master     Ready    control-plane
    k8s-worker1    Ready    <none>

The worker may initially show NotReady while networking initializes.


13. CHECK WORKER DETAILS
------------------------

On the master:

    kubectl get nodes -o wide

    kubectl describe node k8s-worker1


14. CHECK WORKER SERVICES
-------------------------

On the worker:

    sudo systemctl status containerd

    sudo systemctl status kubelet

Both services should be active.


15. CHECK KUBERNETES SYSTEM PODS
--------------------------------

On the master:

    kubectl get pods -A -o wide

System and networking Pods should be distributed across the cluster as
appropriate.


16. VERIFY CONTAINER RUNTIME
----------------------------

On the worker:

    containerd --version

Check the service:

    sudo systemctl status containerd


17. VERIFY KUBELET
------------------

    kubelet --version

    sudo systemctl status kubelet

Check kubelet logs:

    sudo journalctl -u kubelet -xe


18. TEST APPLICATION SCHEDULING
--------------------------------

From the master, create a test deployment:

    kubectl create deployment nginx --image=nginx

Check:

    kubectl get deployment

    kubectl get pods -o wide

The Pod should be scheduled onto a suitable worker node.

After testing, remove the test deployment:

    kubectl delete deployment nginx


19. PROJECT APPLICATION DEPLOYMENT
----------------------------------

The project application is deployed through the Jenkins pipeline.

Jenkins updates the Kubernetes Deployment image:

    kubectl set image deployment/enterprise-devsecops \
      enterprise-devsecops=revanth76/enterprise-devsecops:${BUILD_NUMBER}

The Kubernetes Deployment maintains:

    replicas: 2

The application container listens on:

    8080

The Kubernetes Service exposes the application using:

    NodePort: 30080


20. CHECK APPLICATION PODS
--------------------------

On the master:

    kubectl get pods -o wide

Example:

    enterprise-devsecops-<hash>-<pod-id>    Running
    enterprise-devsecops-<hash>-<pod-id>    Running


21. CHECK APPLICATION SERVICE
-----------------------------

    kubectl get svc

    enterprise-devsecops-service

Check details:

    kubectl describe svc enterprise-devsecops-service

Open:

    http://<KUBERNETES-NODE-PUBLIC-IP>:30080

------------------

Find the application Pod:

    kubectl get pods

View logs:

Follow logs:

    kubectl logs -f <application-pod-name>

-----------------------

The application Deployment uses:

    CPU limit: 500m

Check:

25. MONITORING COMPONENTS
-------------------------

The Kubernetes cluster also runs:

    Prometheus
    Grafana
    Alertmanager
    kube-state-metrics
    Node Exporter

Check:

    kubectl get pods -n monitoring


26. WORKER NODE LABELS
----------------------

Check labels:

    kubectl get node --show-labels

Add a custom label if required:

    kubectl label node k8s-worker1 role=worker

Verify:

    kubectl get nodes --show-labels


27. DRAINING THE WORKER
-----------------------

Before maintenance, the worker can be drained from the master.

    kubectl drain k8s-worker1 --ignore-daemonsets --delete-emptydir-data

After maintenance, make it schedulable again:

    kubectl uncordon k8s-worker1


28. WORKER TROUBLESHOOTING
--------------------------

Check kubelet:

    sudo systemctl status kubelet

Check kubelet logs:

    sudo journalctl -u kubelet -xe

Check containerd:

    sudo systemctl status containerd

Check containerd logs:

    sudo journalctl -u containerd -xe

From the master:

    kubectl describe node k8s-worker1

Check all Pods:

    kubectl get pods -A -o wide


29. COMMON JOIN PROBLEMS
------------------------

If the join token has expired, generate a new one on the master:

    kubeadm token create --print-join-command

If the worker was previously joined to another cluster, reset it before
joining again:

    sudo kubeadm reset -f

Then clean up the old kubeconfig/network state if required and run a new
join command generated by the current master.

Do not reset a production worker without understanding the impact.


30. AWS SECURITY GROUP REQUIREMENTS
-----------------------------------

The worker must communicate with the Kubernetes control plane and other
cluster nodes.

Common worker/control-plane traffic includes:

    TCP 10250    kubelet API
    TCP 30000-32767 NodePort services

Kubernetes networking may require additional ports depending on the CNI
configuration.

For this project, the application NodePort is:

    TCP 30080

Monitoring NodePorts used by the project include:

    TCP 30090    Prometheus
    TCP 30300    Grafana
    TCP 30093    Alertmanager

Restrict sources whenever possible.


31. FINAL WORKER VERIFICATION
-----------------------------

On the worker:

    hostname

    sudo systemctl status containerd --no-pager

    sudo systemctl status kubelet --no-pager

    kubeadm version

    kubelet --version

On the master:

    kubectl get nodes -o wide

    kubectl get pods -A -o wide

    kubectl get svc -A

Expected project state:

    k8s-master     Ready     control-plane
    k8s-worker1    Ready     <none>

Application:

    2 enterprise-devsecops Pods
    STATUS = Running


PROJECT RESULT
--------------

The worker node is successfully configured with containerd, kubeadm, and
kubelet and joined to the Kubernetes control-plane.

The worker provides the compute capacity for application workloads and runs
the Enterprise DevSecOps application Pods scheduled by Kubernetes.
